# 结果解释与写作

先写数据、方法和结果，再将理论、讨论、引言、摘要与实际证据对齐；允许按团队需求调整顺序。每个 RQ 对应样本、模型和证据，结果段说明图表用途、读法、关键数字、不确定性以及假设支持情况，不只复述表格。

结论逐项回答实际 RQ，讨论解释理论含义、竞争解释、不支持假设的原因及边界。结果不显著不证明“没有效应”，不能据此宣布两组相等；系数差异不能仅凭一组显著另一组不显著推断。关联不称“导致”，横截面不写动态更新，外部样本均值不称外国总体真实态度。

正文中每张图/表使用明确标记，例如 `[[Table:T1]]` 或 `[[Figure:F1]]`，前后解释其研究含义和限制。`artifacts/claims.json` 逐条登记关键 N、回归系数、SE 等，正文将声明原文紧接 `[[stat:ID]]`。未登记的数字、比较、引文和图片内容工具不会自动理解，必须人工通读。

文献用 `[[cite:ref-id]]` 映射到 `references.json`，只能登记查到的元数据；核验记录说明实际查阅来源和支持的论点，不仅 DOI 能否打开。缺失字段保留待核验，在内部稿可见，正式提交前处理。工具只保证这些标记的双向覆盖，不自动识别作者—年份等自然语言引文。

语言修订不得提高因果强度、隐藏零结果或扩大代表性。摘要列研究问题、理论视角、样本/设计、方法、核心发现和贡献，所有发现回指实际结果。交付时列哪些自动检查通过、哪些由人检查、哪些尚未解决，不能写笼统“全部通过”。
