# v0.2 架构与设计决策

## 分层

CLI提供人类控制与稳定JSON接口；Skill提供研究指导，不持有实际权限。`runtime`协调固定类型任务DAG，`store`保存事务状态，`schema`验证输入，`statistics`为可信本地适配器，`literature`定位证据与题录，`models`只接收摘要并生成结构化建议，`research`生成计算声明与审阅，`exporting`制作可携带成果包。

模型可以提出方案与文字，但不能调用shell、批准、修改预算或安装依赖。其输出必须通过变量、证据、数字和推断契约。当前不运行任意模型生成Python代码；方法能力扩展必须作为新的已验证适配器交付。

## 状态与证据

每个schema2项目的`.cra/state.sqlite`含meta、objects、versions、edges、tasks、approvals、calls、events、leases表。对象采用规范JSON与SHA256，历史版本不覆盖；依赖边驱动过期传播。事务包括对象/任务状态/事件更新，任务产物先原子写入文件再登记。若文件写完而事务未提交，重启会重建，不将孤立文件视为成功。

任务为audit、corpus、protocol、analysis、claims、draft、method_review、evidence_review。执行顺序由依赖决定，目前单进程顺序调度；可配置并发上限不超过2，但尚未实现并行执行。状态独立于六个研究阶段。

authorization只绑定brief；protocol绑定brief、数据、代码本、审计、文献与方案；final进一步绑定分析、声明、稿件与两个审阅。叙述源变化不使分析/计划冻结失效，无关文件也不使核查失效。正式生成文件被手工修改时，不收编为可信结果，而是标记对应任务及下游过期。

人工批准由交互CLI接收，绑定证据快照，不提供`--yes`；模型工具集中没有批准入口。同一OS账号仍能直接修改数据库或调用Python方法，因此这属于研究流程边界而非身份/攻击防护系统，日志也不是数字签名。

## 执行与隔离

macOS使用Seatbelt禁止网络和越界写入，只对运行目录及明确输入/代码/运行时放行私有文件读取。Linux使用bubblewrap用户/网络等命名空间、只读运行时和输入挂载，运行目录可写。运行前用真实子进程探测网络、控制数据库读取、越界写入是否被禁止；失败时不降级到无隔离执行。

worker运行环境不继承API密钥或用户环境，stdout/stderr不传给模型。只返回结构化结果或不含原值的错误。统计脚本是随包发布的可信代码，不接收模型源代码。未知外部脚本没有自动执行接口。开发候选已完成Ubuntu 24.04云端Linux工程集成；这不是独立真人验收。Windows不宣称支持。

## 模型与网络

控制进程按brief中明确主机授权调用兼容chat/completions接口。启用前实际测试echo工具调用往返和JSON响应；更换配置失效。带bearer的请求不跨主机重定向，HTTPS为默认，只有loopback测试允许HTTP，禁用隐式代理以避免将数据交给未授权代理。

模型上下文只由受控摘要、聚合统计、计划、计算声明和明确许可文献片段组成。不读取统计原始输出、行级数据、残差和聚类ID。敏感模式、分组阈值与模型提示只是多道检查，不保证识别全部自由文本敏感性或重识别风险。

Crossref题录检索/核对只证明元数据关系。PDF页码/段落中的精确引文查找只证明文本存在，不证明语义支持。supported/metadata_declaration均保留研究者声明与局限。模型审阅不能变成人类核查。只有题录时停止理论方案，不伪造全文。

## 预算、暂停与崩溃

发起模型调用前在事务内预留基于输入字节上限与输出token上限的保守费用；真实usage到达后结算。用量缺失、网络结果未知或进程崩溃后，保留uncertain预留并禁止自动重发。人对账后显式结算。服务商实际计费差异可以超出估算，系统会记录且不继续调用；不承诺控制外部账单。

租约防止两个调度器同时运行。进程崩溃后，已完成任务复用，running任务恢复，reserved付费请求变为uncertain。没有任意重放付费HTTP。统计子进程超时或暂停时终止进程组；HTTP在配置/剩余授权时长内结束。相同错误连续两次停止；输入变化后可重新尝试。文字修订最多两轮，研究变量/模型等实质变更必须重新冻结。

## 方法边界

OLS/WLS/二元Logit的数字来自statsmodels实际执行；WLS只接受明确逆方差权重，调查权重只用于描述均值。HC3仅非加权OLS；单维聚类少于30时当前适配器保守停止。复杂抽样、SEM、多层、跨国等值性与因果识别尚无专用适配器。

数字稿件用规范结果和锚点编译，模型不能自己填写统计数值。未标记自然语言语义、理论贡献、全部引用支持及完整投稿格式仍需人审。DOCX保留内部引文键，不宣称是完整APA/GB/T排版器。

## 迁移与分发

新console可调用随wheel打包的原v1脚本，原独立脚本原文保留。migration dry-run不创建状态文件；正式迁移先备份目录，旧审核只存历史，新批准为空。统计依赖放在engine extra，不强制旧标准库工作流安装。研究包带实际recipe源码与环境版本，不含API密钥或控制库，数据默认不共享。

## 仍由发布验收解决的问题

三个真实授权项目及双角色终审、研究方法保留集的专家评分、真实模型质量、主动操作时间降低指标、完整期刊排版和分布式/恶意攻击防护，均不由模拟软件测试替代。开发候选的 Linux 真实隔离工程集成已通过，见发布准备记录；它不是独立真人验收。

## 开发候选中的统计版本与失败证据

`statistics_recipe` 保存统计实现、执行器、公共函数、隔离器及包版本文件的内容哈希，以及 Python 和四项数值依赖版本。安装路径不纳入身份，因此仅移动相同软件不会使结果过期。代码或环境变化会使受影响的审计、分析、稿件及终审失效，文献等无关材料可复用。

统计产物中的 `recipe_identity` 与实际源码一起导出。即使普通文件清单重新计算了哈希，替换统计源码仍会被成果包检查拒绝。复现须匹配记录的 Python、依赖和输入；不能仅凭数字相近而声称环境一致。

计划冻结同时绑定已完成审计。升级前没有统计版本绑定的历史产物不自动取得新范围；历史批准保留，但当前证据仍须满足快照。若重新审计后证据和研究方案均未改变，已有的相同方案批准可继续使用；重新计算的结果仍需新的成果终审。

每项模型开始前和结束后原子保存进度。后续模型失败时，记录此前模型的完整结果、当前失败指纹和其余未执行状态；worker进度文件的哈希进入状态记录，并随诊断包导出。部分进度始终标为未完成研究，不生成虚假的最终分析或结论。
